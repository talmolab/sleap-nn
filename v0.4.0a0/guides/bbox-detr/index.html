    DETR box detector (bbox_detr)¶

    bbox_detr is a box detector modeled on RF-DETR (Robinson et al., ICLR 2026). It predicts a set of boxes per frame: each of a fixed number of queries either claims one animal or predicts "nothing". Training matches queries to animals one to one (Hungarian matching), so the model learns not to predict duplicates, and there is no NMS step at inference. Two animals that touch or overlap stay two boxes; with CenterNet or SSD, NMS or merged heatmap peaks can turn them into one.

    Use it as:

    • a standalone detector (boxes written as sio.PredictedBoundingBox), or
    • the first stage of a top-down pose model, in place of the centroid model (Top-down with a box detector), or
    • the source of detector boxes for training crops (sleap-nn detect-boxes).

    It is detection only by default (no mask head); an experimental keypoint branch predicts keypoints in the same pass (see Boxes and keypoints in one pass).

    bbox_centernet / bbox_ssd bbox_detr
    Backbone UNet / ConvNeXt / SwinT pretrained plain ViT (DINOv3, or RF-DETR's windowed DINOv2)
    Output dense maps, decoded + NMS 100–300 boxes with scores, no NMS
    Touching animals can merge stay separate
    GPU memory (training) 1–4 GB ~4–8 GB for ViT-S at batch 4–8, more for ViT-B or large inputs
    Data needed a few hundred frames a few hundred frames, but more epochs (> 100)

    The Bounding-box detection guide covers what all bbox_* models share: where training boxes come from, evaluation (eval/val/bbox_mAP, sleap-nn eval --match_method bbox) and the output format.

    How it works¶

    frame (letterboxed to max_height x max_width)
  -> ViT (DINOv3 ViT-S/B, or windowed DINOv2-S), 16 x 16 px tokens; blocks 3, 6, 9, 12 tapped
  -> projector: concat the 4 taps -> C2f -> one 256-channel map at stride 16
  -> two-stage proposals: every token proposes a box; the top num_queries become queries
  -> decoder (2-4 layers): self-attention between queries, deformable attention into the map
  -> per query: class scores (sigmoid) + box (cx, cy, w, h)

    Training uses RF-DETR's recipe: 13 query groups (Group DETR), IoU-aware BCE class loss plus L1 and GIoU box losses on every decoder layer and on the proposals, AdamW, a lower learning rate for the backbone with layer-wise decay, weight EMA, gradient clipping and bf16. Each class bias starts at the 0.01 prior, so the model starts by predicting "nothing" everywhere.

    Train an animal detector from a DINO backbone¶

    "From scratch" here means: pretrained DINOv3 ViT, randomly initialized projector and decoder, no detection checkpoint. This is the default for animals.

    The quickest start is the config generator, which sizes everything from your labels:

    sleap-nn config labels.slp --auto --pipeline bbox_detr -o detector.yaml
# or the pair (detector + box-scaled centered-instance model):
sleap-nn config labels.slp --auto --pipeline topdown_bbox_detr -o animals.yaml
#   -> animals_bbox_detr.yaml + animals_centered_instance.yaml
sleap-nn train detector.yaml

    Or start from the sample config config_bbox_detr_dinov3_s_animals.yaml, which explains each value. It was written for a small dataset of two animals per frame (1,180 training frames at 1280 x 1024). The parts that matter:

    data_config:
  bbox_source: instances   # one box per pose instance: its visible nodes
  bbox_padding: 9.0        # px on every side; 5% of the median animal size
  preprocessing:
    ensure_rgb: true       # DINOv3 reads RGB; gray frames are repeated
    max_height: 512        # input size: see "Choosing the input size"
    max_width: 640
    resize_mode: letterbox
  augmentation_config:
    geometric: null        # no rotation: it inflates keypoint boxes
    detr:                  # RF-DETR's crop / flip / multi-scale, scaled to the input
      crop_p: 0.5
      shortest_sides: [512]
      crop_range: [341, 512]
      flip_p: 0.5
      multi_scale: true
      multi_scale_steps: 5
model_config:
  backbone_config:
    pretrained:
      model_name: timm/vit_small_patch16_dinov3.lvd1689m
      weights: true
      mode: tokens
      layers: [3, 6, 9, 12]
      drop_path_rate: 0.1
      max_stride: 32
  head_configs:
    bbox_detr:
      detr:
        categories: null   # one class, filled from the boxes ("object")
        num_queries: 100
        num_select: 100
        dec_layers: 3
trainer_config:
  max_epochs: 200
  min_train_steps_per_epoch: 1
  optimizer_name: AdamW
  optimizer: {lr: 1.0e-4, weight_decay: 1.0e-4, encoder_lr_scale: 1.5, layer_decay: 0.8}
  lr_scheduler: {reduce_lr_on_plateau: null}   # constant LR
  early_stopping: {stop_training_on_plateau: false}
  ema: {enabled: true, decay: 0.993, warmup_steps: 100}
  gradient_clip_val: 0.1
  precision: bf16-mixed
  eval: {enabled: true, frequency: 1}           # keeps the best eval/val/bbox_mAP

    The pretrained backbone needs the backbones extra (pip install "sleap-nn[backbones]") and downloads the DINOv3 weights from the HF Hub on first use (see Pretrained Backbones for offline use).

    Boxes. A pose project has no boxes, so they are derived from the poses: the tight box of each instance's visible nodes, plus bbox_padding pixels on every side. Keypoints sit inside the animal's outline (the nose, ears and tail base of an animal seen from above do not reach its flanks), so a little padding makes the box cover the body. Use the same bbox_source and bbox_padding in the centered-instance model of a top-down pair: its crops are then the same boxes the detector learns.

    Classes. Leave categories: null for one class. Boxes derived from poses have no category, so the class is named object. If your labels carry user boxes with categories, each category becomes a class (only boxes of the listed categories are ground truth when you set categories yourself).

    Choosing the input size¶

    The ViT sees the frame as 16 x 16 px tokens, and the detector reasons about animals in tokens. An animal under about 3 tokens across is often missed. The config generator's rule (recommend_detr_resolution):

    1. Take the animal size as sqrt(w * h) of the padded training boxes (it varies less with the animal's orientation than the longer side does).
    2. Pick the smallest scale at which the small animals (5th percentile) are at least 3 tokens (48 px) across and the median animal at least 4 tokens, never above the frame's own resolution.
    3. Round the letterboxed frame up to multiples of 32; at least 384 px on the long side, at most 1280 px.
    Dataset Frames Animals (p5 / median, padded) Input Small / median animal
    A small arena (2 animals) 1280 x 1024 97 / 191 px 640 x 512 3.0 / 6.0 tokens
    A home cage (2 animals) 720 x 480 79 / 104 px 448 x 320 3.1 / 4.0 tokens
    A large arena (6 animals) 3934 x 3490 87 / 169 px needs 2170; capped at 1280 x 1152 1.8 / 3.4 tokens

    Compute cost grows with the number of tokens (global attention: with the square of it, though flash attention keeps memory linear), so the rule does not go bigger than it needs to. The Input: line of sleap-nn config --auto output (and the TUI's DETR panel) shows the result and a warning when the cap was hit. For that case see Large arenas.

    num_queries must not exceed the tokens of the smallest training size (100 queries need at least 160 x 160 px). Multi-scale training drops sizes that would have fewer tokens than queries.

    Backbone sizes¶

    ConfigGenerator.detr(preset=...) (or the TUI's DETR panel) switches the backbone and decoder. Parameter counts are for one class and 100 queries; GPU memory is the generator's estimate for training at the preset's default input with multi-scale on (calibrated on a measured RF-DETR-M run; expect ± 30%).

    Preset Backbone Decoder layers Default input Parameters GPU memory, batch 4 / 8
    dinov3_s (default) DINOv3 ViT-S/16 3 from the data (640 above) 30.7M 4.4 / 8.1 GB at 640
    dinov3_b DINOv3 ViT-B/16 4 from the data (704 for people) 96.7M 10.4 / 18.9 GB at 704
    rfdetr_n windowed DINOv2-S 2 384 29.5M 2.4 / 4.1 GB
    rfdetr_s windowed DINOv2-S 3 512 31.1M 3.3 / 6.0 GB
    rfdetr_m windowed DINOv2-S 4 576 32.7M 3.9 / 7.2 GB
    rfdetr_l windowed DINOv2-S 4 704 32.9M 5.1 / 9.5 GB

    Without init_from, the rfdetr_* presets start the windowed DINOv2-S from the plain facebook/dinov2-small weights with a fresh decoder. With init_from pointing at an imported RF-DETR model they fine-tune it (next section).

    Import RF-DETR¶

    RF-DETR's Apache-2.0 checkpoints (nano, small, medium, large) convert to sleap-nn model directories. The other RF-DETR sizes (the XL / 2XL and "plus" models) are under a different license (PML 1.0) and have no short name here; a Hub id or directory you pass carries its own license, which sleap-nn does not check.

    sleap-nn import-rfdetr medium -o models/rfdetr-medium      # downloads Roboflow/rf-detr-medium
sleap-nn predict -m models/rfdetr-medium -i video.mp4      # 91 COCO-id classes

    The import needs huggingface_hub and safetensors (the backbones extra). The output loads like a trained bbox_detr model. It keeps RF-DETR's square squash resize (resize_mode: squash) at the checkpoint's resolution (384 / 512 / 576 / 704 for N / S / M / L): RF-DETR's weights degrade with letterboxing. The imported RF-DETR-M scores 54.7 box AP on COCO val2017, matching RF-DETR's published number.

    Fine-tune to new classes¶

    Start a training run from any bbox_detr model with model_config.init_from: tensors with the same name and shape are copied, and the class heads' rows are copied by class name. Keep the source's architecture (backbone, dec_layers, num_queries) to reuse all of it: a different query count leaves the learned query embeddings fresh. A class that the source model does not have starts fresh at the 0.01 prior; the rest of the detector (backbone, projector, decoder, box heads) is reused.

    data_config:
  preprocessing:
    max_height: 576
    max_width: 576
    resize_mode: squash          # as the imported weights were trained
model_config:
  init_from:
    path: models/rfdetr-medium
    # Optional: seed new classes from related source classes, {target: source}.
    # node_map:
    #   animal: cat
  backbone_config:
    dinov2_windowed: {...}       # as in the imported model's training_config.yaml
  head_configs:
    bbox_detr:
      detr:
        categories: [animal]     # "animal" is new: its row starts fresh
        dec_layers: 4
        num_queries: 300         # RF-DETR's; fewer and its query embeddings start fresh
        num_select: 300

    Don't map __extra__, the never-positive extra logit. Unmapped, it takes the source's own extra logit, which is never positive either. Seeded from a real class ({__extra__: person}), it starts out scoring like that class, so at every object the loss pushes it down through the same decoder features that score the class. On RF-DETR-L fine-tuned on COCO persons, this term was 4.6 of the 7.8 step-0 classification loss, and its gradient on the shared weights was 2.5x the person gradient.

    The config generator writes this for you (an rfdetr_* preset with init_from switches to squash and 300 queries):

    from sleap_nn.config_generator import ConfigGenerator

gen = ConfigGenerator.from_slp("labels.slp").auto().pipeline("bbox_detr")
gen.detr(preset="rfdetr_m", init_from="models/rfdetr-medium").save("detector.yaml")

    Worked examples: config_bbox_detr_rfdetr_m_person.yaml (RF-DETR-M cut to a person-only COCO detector, 20 epochs at 4 x 4 images per step). RF-DETR's own fine-tuning advice applies: if training does not converge, halve the learning rate.

    Another bbox_detr model works as the source the same way, e.g. a person detector to start a detector for another species. Its backbone must have the same shape (same preset).

    Example: a person detector in two stages¶

    The sample person-detector recipe trains in two stages on DINOv3 ViT-B/16 at 704 px, letterboxed:

    1. config_bbox_detr_dinov3_b_person.yaml: fresh projector and 4-layer decoder on the person boxes of Objects365 + Open Images, 12 epochs at 4 x 8 images per step, lr 2e-4.
    2. config_bbox_detr_dinov3_b_person_stage2.yaml: every tensor from stage 1 (init_from), then COCO + CrowdHuman + CrowdPose + JRDB-Pose + Human-Art mixed per sample by trainer_config.balanced_sampler (per_sample: true, weights 0.4 / 0.2 / 0.1 / 0.1 / 0.2), 50 epochs of 100K samples, lr 1e-4.

    Only boxes of the configured categories are ground truth (categories: [person]): faces, heads, crowd and ignore regions in those datasets are skipped, and frames left with no person box are not sampled.

    Top-down pose with a DETR first stage¶

    Train the detector and a box-scaled centered-instance model (the config generator's topdown_bbox_detr writes both), then pass both to predict:

    sleap-nn train animals_bbox_detr.yaml
sleap-nn train animals_centered_instance.yaml
sleap-nn predict -i video.mp4 -m models/animals_bbox_detr -m models/animals_centered_instance
sleap-nn eval --ground_truth_path test.slp --predicted_path test.predictions.slp

    Each detected box is padded, squared and resized to the instance model's crop size (crop_mode: bbox), and kept in the output linked to the pose instance it seeded. --peak_threshold is the detection score threshold and --max_instances caps the boxes per frame. Everything else is as in Top-down with a box detector.

    Detector boxes for training crops¶

    Experimental

    Training on detector-box crops (sleap-nn detect-boxes, then crop_bbox_source: detector) may change or be removed without a deprecation period. In the developers' test its gain over ground-truth-box crops was within noise.

    At inference the instance model sees crops from detector boxes, which are slightly off from the ground-truth boxes it trained on. sleap-nn detect-boxes runs a detector over the labeled frames and stores its boxes, matched to the instances, so the instance model can train on detector-box crops:

    sleap-nn detect-boxes -i train.pkg.slp -m models/animals_bbox_detr --category animal
# -> train.pkg.bboxdetr.slp: one PredictedBoundingBox per detection (score >= 0.3),
#    linked to its matched instance; match statistics in <output>.json

    Matching is Hungarian on IoU per frame, against each instance's user box or, in a pose project, its keypoint extent. A single-class detector's class is used as --category, which also names the new boxes. Then train the instance model on the new file with the warp data path and crop_bbox_source: detector (see Detector-box crops).

    Large arenas and tiling¶

    When the token rule asks for more than 1280 px (small animals in a large arena), you have three options today:

    • Raise the input size. Set max_height / max_width past the cap (ConfigGenerator.detr(max_side=...)). Memory grows with the token count: the estimate for ViT-S at batch 4 is ~11 GB at 1280 px and ~23 GB at 1920 px; lower the batch size to fit.
    • Crop the arena to the area the animals can reach, if the camera is fixed.
    • Use a centroid first stage with tiling (Tiling) for frames far beyond that.

    Tiled inference is not implemented for bbox_* models in sleap-nn predict yet. sleap-nn detect-boxes --tile_width W has a full-height tiled mode for very wide frames (panoramas), merging the tiles' boxes with an edge-aware NMS.

    Training already sees zoomed-in views: half of the training samples go through RF-DETR's crop branch, a random square crop of ⅔ to all of the frame's short side, resized to the input size.

    Small datasets¶

    Advice for a few hundred to a few thousand labeled frames, as in the two-animal sample:

    • Train long. The RF-DETR paper says small datasets need more than 100 epochs. The sample uses 200 (one epoch = one pass over the frames, min_train_steps_per_epoch: 1). Keep the LR constant and early stopping off; the EMA weights keep improving after the loss flattens, and the checkpoint with the best eval/val/bbox_mAP is kept.
    • Use fewer queries. 100 instead of RF-DETR's 300. Frames hold a few animals; fewer queries train faster and need fewer tokens.
    • Prefer ViT-S. DINOv3 ViT-S with a 3-layer decoder has 31M parameters, most of them pretrained. ViT-B is worth it for varied scenes (many setups, lighting, species), not for one arena.
    • No rotation. Rotating a keypoint box makes it bigger than the rotated animal. RF-DETR's crop and flip, multi-scale and brightness / contrast give enough variety. Keep geometric: null explicitly: an omitted section falls back to the default (± 15 degree rotation).
    • Check the boxes. Look at a few training frames with their derived boxes (e.g. render LabeledFrame.bboxes); raise bbox_padding if boxes cut off the body.
    • Keep the batch, adjust the LR. The sample uses batch 8 at lr 1e-4 (RF-DETR: 16 per step at 1e-4). Halve the LR if the loss spikes or bbox_mAP stays near 0 after 20-30 epochs.
    • Start from another detector when one exists for a similar domain (init_from, previous section). Whether a detector of another species helps is not settled; compare against a start from the backbone alone.

    Training augmentation¶

    Besides RF-DETR's crop, flip and multi-scale (above), augmentation_config.detr has options that RF-DETR does not. All are off by default and apply to training frames only. They run in this order: RF-DETR's crop branch, horizontal flip, vertical flip, 90 degree rotation, the fit to the input size, zoom-out, then copy-paste; the intensity / geometric sections come after (with frame_photometric, the intensity ops run first, on the whole frame).

    Zoom-out¶

    Zoom-out shrinks the fitted training frame and places it at a random spot on a canvas of the input size, so the detector also sees animals smaller than in the labelled frames (a camera farther away, a larger arena). The factor is drawn log-uniformly from [zoom_out_min, zoom_out_max]; boxes shrink and move with the frame. In the developers' tests it was the one option in this section that improved detection in recording setups not seen in training.

    data_config:
  augmentation_config:
    detr:
      zoom_out_p: 0.5         # share of training frames that are zoomed out
      zoom_out_min: 0.4       # smallest factor (0.4 = 40% of the input size)
      zoom_out_max: 1.0
      zoom_out_canvas: frame  # zero (black) or frame (another training frame)
    Key Default Meaning
    zoom_out_p 0.0 (off) Probability of zooming a training frame out
    zoom_out_min 0.4 Smallest factor (> 0)
    zoom_out_max 1.0 Largest factor (<= 1)
    zoom_out_canvas zero zero: a black canvas. frame: another training frame (a uniformly drawn file, then frame), fitted to the input size with its own boxes; its boxes at least half covered by the shrunk frame are dropped and the others clipped to the part left visible, so the surroundings are real scenes

    With zoom_out_canvas: frame a sample can hold the boxes of two frames, so the largest number of boxes per sample (max_instances) is doubled. The CenterNet and SSD box heads (bbox_centernet, bbox_ssd) take the same zoom-out keys.

    Vertical flip and 90 degree rotation¶

    For overhead video, where no orientation is special, vflip_p flips frames upside down and rot90_p turns them by 90 degrees (clockwise or counterclockwise at random). Both keep boxes exact, unlike the geometric rotation, whose turned box corners enlarge the boxes. With flip_p: 0.5, vflip_p: 0.5 and rot90_p: 0.5 every orientation and mirror image is equally likely. They are available with no measured gain in the developers' tests.

    Key Default Meaning
    vflip_p 0.0 (off) Vertical flip probability
    rot90_p 0.0 (off) Probability of a 90 degree rotation, either direction

    Boxes are clipped to the frame before it is fitted to the input size, so a box reaching past the frame's right or bottom edge (an animal cut by a random crop, or a padded keypoint box at the frame edge) is not kept over the letterbox padding.

    Copy-paste¶

    Experimental

    Copy-paste may change or be removed in a later release without a deprecation period, and it showed no measured benefit in the developers' tests.

    Copy-paste cuts animals out of other training frames and pastes them onto the fitted training frame: more animals, small animals and new backgrounds per sample. Each animal is its box region with a soft mask (the convex hull of its linked instance's points inside the box, dilated and feathered), scaled by a log-uniform factor, flipped and turned by a multiple of 90 degrees at random, and placed inside the frame's content (not on the letterbox padding). Boxes with no linked instance, or with fewer than 4 points inside, are never pasted, so this needs pose labels.

    Key Default Meaning
    paste_p 0.0 (off) Probability of pasting into a training frame
    paste_max 6 Most animals pasted into one frame (a uniform draw from 1 to this)
    paste_frames 2 Most source frames read per paste (each a uniformly drawn training file, then frame)
    paste_scale_min 0.3 Smallest scale of a pasted animal, relative to its size in its own fitted frame
    paste_scale_max 1.2 Largest such scale
    paste_overlap 0.3 Largest share of a pasted box that may overlap boxes already in the frame (a pasted box never covers half of another box)
    paste_dilate 0.08 Mask dilation, as a share of the box's longest side
    paste_feather 0.04 Mask edge blur (Gaussian radius), as a share of the box's longest side

    With copy-paste on, max_instances grows by paste_max.

    Appearance augmentations on whole frames¶

    augmentation_config.intensity.frame_photometric: true (experimental) applies the warp data path's photometric ops, including the experimental appearance ops (grey, channel shuffle and gain, gamma, invert, down-up, JPEG), to whole detector training frames. See Appearance augmentations.

    Boxes and keypoints in one pass (experimental)¶

    A bbox_detr model can also predict each animal's keypoints, so one network gives boxes and poses in a single forward pass (no second, top-down stage). Each decoder query regresses its keypoints as offsets from its predicted box center, in units of the box's width and height, plus one visibility logit per keypoint (box-relative keypoint queries in the manner of ED-Pose, Yang et al. 2023, and PETR, Shi et al. 2022; RF-DETR's keypoint preview models also predict boxes and keypoints in one pass). Turn it on with one section:

    model_config:
  head_configs:
    bbox_detr:
      detr:
        keypoints:
          part_names: null        # null: the first training file's skeleton nodes
          loss_weight: 5.0
          visibility_loss_weight: 1.0
          visibility_threshold: 0.5

    What it does:

    • Training. Hungarian matching stays on boxes. Each matched query gets an L1 loss on its located points, divided by the target box's size, and a binary cross-entropy loss on visibility. Both are weighted per node by the partial-label weights: a node a file does not label (labeled_nodes, or the per-point labeled flag) gets no loss. Each loss is a weighted mean over the batch's points (divided by the summed weights, at least 1), so loss_weight means the same whether half the boxes have no pose or a file labels half the nodes. The sums are per process: with several GPUs each one averages its own batch (the box losses' normaliser is shared across them). Every decoder layer is supervised (as for the boxes); the encoder proposals are not. The keypoint branch does not train the box: the box is detached where the points are read from it.
    • Visibility. The target is 1 when the point is labelled with a location in the model input, else 0. Labelled occluded points with estimated coordinates count as located under data_config.supervise_occluded: true (the default) and get no loss under false. A point covered by an augmentation (a pasted animal, or the shrunk frame in zoom-out onto another frame) is treated the same way: it keeps its location (default) or loses its weight. Points pushed out of the input (outside a crop or the frame) and labelled points without coordinates are trained as not visible; so are a pasted animal's points that lie outside its box (only its box is pasted), which can happen with drawn boxes that cut off a body part.
    • Data. Boxes are linked to pose instances (box.instance; boxes derived with bbox_source: instances always are), and each box's points ride along with it through every training augmentation: the resize (letterbox or squash), RF-DETR's crop, the mirror flips (with the skeleton's left/right pairs swapped), the 90 degree turns, zoom-out (on a black canvas or on another frame, whose animals bring their own points), copy-paste (a pasted animal brings its points) and the stock geometric augmentation. A box with no linked instance, or whose instance has no labelled node among part_names, trains its box only. A training or validation file with no box that has a pose gets a warning saying which of the two it is, and a training set with none at all is an error (the keypoint branch would train nothing). The resizes scale points as sleap-nn does everywhere (x * s, undone as x / s at prediction), while the flips and turns map pixel centers (W - 1 - x); a scaled and flipped sample therefore carries up to half a pixel of label noise.
    • Skeleton. The model's skeleton is part_names (by default the nodes of the first training file's skeleton, written into the saved config) with every edge and symmetry the files have between them. Files are matched by node name (integer labeled_nodes entries are read against each file's own skeleton); a node a file lacks is unlabelled there.
    • Prediction. sleap-nn predict -m <model_dir> writes one predicted instance per detection, linked to its box (box.instance), with the box score as the instance score and each point's visibility probability as its score. Each query gives at most one detection, of its best category. Points below visibility_threshold are written as missing; a detection with no point above it keeps its box but gets no instance. visibility_threshold is read from the model's training_config.yaml (edit it there; sleap-nn predict has no option for it).

    Not supported yet: ONNX / TensorRT export of such a model (refused with a message; run it from its checkpoint; a detector and top-down model pair is not exportable as one bundle for any detector), box distillation into a keypoint student (refused), keypoint matching costs, OKS-based losses, and keypoints in the training gallery and epoch-end evaluation (which score boxes only). With more than one category, the epoch-end box metrics (and the checkpoint they select) still decode (query, category) pairs as for a box detector, so one query can count as two detections there, while prediction gives one detection per query; with one category the two are the same.

    Configuration reference¶

    All bbox_detr keys are in the configuration reference: head_configs.bbox_detr.detr, backbone_config.dinov2_windowed, backbone_config.pretrained.mode: tokens, init_from.node_map, preprocessing.resize_mode, augmentation_config.detr, trainer_config.balanced_sampler.per_sample and the optimizer's encoder_lr_scale / layer_decay.

    Export (ONNX / TensorRT)¶

    sleap-nn export models/my_detr -o models/my_detr/exported --format both --precision bf16
sleap-nn predict -m models/my_detr/exported -i video.mp4 -o boxes.slp

    The default fp16 keeps each attention block's logits product in fp32 for this encoder (TensorRT 10.13 or later; see fp16 for ViT backbones). A plain fp16 engine (TensorRT below 10.13, or --no-fp32-attention-logits) can lose boxes with a DINOv3 encoder: pass --precision bf16 (a GPU with compute capability

    = 8.0) or fp32 there. sleap-nn predict prefers the TensorRT engine when the directory holds one. In bf16 the layers after the backbone (proposals, decoder, box head) are kept in fp32; see TensorRT precision.

    As for the other detectors (Box detection), the graph holds the network only (pred_logits, pred_boxes of the final decoder layer) and the exported-model adapter rebuilds the set decoder (num_select top-k) and the resize (resize_mode, max_height / max_width) from the copied training_config.yaml, so the host-side steps are the checkpoint path's own.

    A bbox_detr graph takes a float32 input by default (--input-dtype auto): it receives the checkpoint path's own resized frame, so exported boxes match checkpoint inference up to the runtime's numerics. --input-dtype uint8 (the other detectors' convention) is available: the host then resizes the frame in float and rounds it, while checkpoint inference resizes it in the frame's own dtype; the canvases differ by up to one grey level, and the two-stage query selection (a top-k over many near-tied proposals) can turn that into slightly different boxes and scores (a small share of boxes slightly shifted and scores a few hundredths apart -- the same as PyTorch itself on that canvas).

    Limits¶

    • No per-query mask head; the keypoint head is experimental (see Boxes and keypoints in one pass).
    • No tiled inference in sleap-nn predict (see above).
    • An exported bbox_detr with a rotary-position encoder (DINOv3) runs at its traced input size only (max_height x max_width; the host letterboxes or squashes every frame to it, so this is no restriction in sleap-nn predict).
    • precision: bf16-mixed needs an Ampere or newer GPU; use "32" otherwise.
