# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

sleap-nn is a PyTorch-based neural network backend for animal pose estimation.

## Notes
- We use `uv` for environment management and packaging.
- We use `sleap-io` (https://github.com/talmolab/sleap-io) as the I/O backend for `.slp` files, which are HDF5-based containers for labels and sometimes embedded image data (typically ending with `.pkg.slp`). Refer to https://raw.githubusercontent.com/talmolab/sleap-io/refs/heads/main/docs/examples.md for usage examples when you need to do I/O with SLP files.
- This package (`sleap-nn`) is used as the neural network training backend to SLEAP, which is primarily used through its frontend package `sleap` (https://github.com/talmolab/sleap).

## Architecture Overview

The codebase follows a modular architecture:

### Core Components

1. **Model Architecture** (`sleap_nn/architectures/`)
   - Backbone networks: UNet, ConvNext, SwinT (via `model.py:get_backbone`)
   - Head modules for different tasks: confidence maps, centroids, PAFs, etc.
   - Model configuration via Hydra/OmegaConf

2. **Data Pipeline** (`sleap_nn/data/`)
   - Providers for reading SLEAP files (`providers.py`)
   - Data augmentation, normalization, resizing
   - Confidence map and edge map generation
   - Instance cropping and centroid computation

3. **Training System** (`sleap_nn/training/`)
   - Lightning-based training modules (`lightning_modules.py`)
   - ModelTrainer class for orchestrating training (`model_trainer.py`)
   - Custom losses and callbacks
   - Configuration via `TrainingJobConfig`

4. **Inference Pipeline** (`sleap_nn/inference/`)
   - Different predictors for each model type (single instance, top-down, bottom-up)
   - Peak finding and PAF grouping for multi-instance
   - Unified prediction interface via `predictors.py`

5. **Tracking** (`sleap_nn/tracking/`)
   - Instance tracking across frames. `TrackerConfig.tracker` / `--tracker` selects the
     family: `classic` (default, `tracker.py`) or a modern MOT tracker (`mot/`).
   - Classic: candidate generation with fixed windows and local queues
   - Classic candidate-update motion models: optical-flow (`FlowShiftTracker`, `--use_flow`) and
     Kalman filter (`KalmanShiftTracker`, `--use_kalman`; requires a target instance count
     and `pykalman`). Both subclass `Tracker` and override only `update_candidates`.
   - Modern MOT trackers (`sleap_nn/tracking/mot/`, numpy/scipy, original BSD code — never
     copy the GPL references): `sort`, `deepsort`, `strongsort`, `bytetrack`, `botsort`,
     `ocsort`, `deepocsort`, all subclasses of `base.BaseMOTTracker` that implement only
     `_associate` (per-paper Kalman filters in `kalman.py`, matching in `association.py`,
     quality-gated appearance memory in `appearance.py`). `params.MOTParams` holds the
     per-tracker presets (`animal` default / `paper`) plus `--mot_param KEY=VALUE`
     overrides. `calibration.calibrate` self-calibrates each video before tracking:
     geometry, time base, and the appearance DECISION-statistic thresholds behind
     `appearance_threshold="auto"`, which turns appearance OFF when it does not
     discriminate. Animal presets divide every score by the video's q95
     (`normalize_scores`); `body_size` comes from a measured/motion/spacing/50 px chain
     (`--mot_param body_size=` overrides). ONE clock (`calibration.frame_steps`) and ONE
     usable-vector rule (`detections.has_usable_embedding`: present, finite, non-zero) are
     shared by calibration, trackers, linker and `apply_tracking`'s checks.
     `linking.link_tracklets` is offline identity linking (gap re-ID with per-query-length
     calibrated thresholds, swap correction, anchor-based closed set via `max_tracks`); it
     runs in `finalize()` and also after `classic` with `--link_tracklets` (which then
     accepts `--mot_param time_base=/body_size=` and nothing else). Perf refactors of the
     trackers must be bit-identical (seeded hash of track names/scores). Routed by
     `inference/tracking.py::apply_tracking` → `_apply_mot_tracking`, which writes
     `labels.provenance["tracking"]` (`videos[k]["video"]` = index into `labels.videos`,
     plus `video_filename`; the record always describes the latest run).
   - `sleap_nn/tracking/mot_metrics.py`: TrackEval-faithful CLEAR-MOT / Identity / HOTA
     core; `evaluation.compute_mot_metrics` is the sio adapter (the `"mot"` block of
     `eval-tracking`).

### Configuration System

The project uses a hierarchical configuration system with three main sections:
- `data_config`: Data pipeline configuration
- `model_config`: Model architecture configuration  
- `trainer_config`: Training hyperparameters and Lightning configuration

Configurations are managed via Hydra and can be specified in YAML files (see `docs/config_*.yaml` examples).

### Key Entry Points

- Training: `sleap_nn/train.py` - Hydra-based training entry point
- Inference: `sleap_nn/legacy_predict.py` - Run inference on trained models
- CLI: `sleap_nn/cli.py` - Command-line interface (currently minimal)
- Evaluation: `sleap_nn/evaluation.py` - Model evaluation utilities
- Centroid-only models: first-class support — train a lone centroid head, `sleap-nn predict` auto-detects a single centroid directory (output collapses to a single-node `'centroid'` skeleton), distance-based eval (`--match_method centroid`), and standalone ONNX/TensorRT export. See `docs/guides/centroid-only-inference.md`.
- Peak refinement / flip-test: `--integral_refinement` (`PostprocessConfig.refinement`) is `auto|dark|integral|local|none`, default `auto`, resolved per peak finder by `inference/ops/peaks.py::resolve_refinement`. `auto` = DARK (`dark_refinement`: Newton step on the log confmap after a blur of `dark_blur_sigma` = the head's training `sigma`, set by the loaders) for the top-down keypoint stage (`centered_instance`, `multi_class_topdown`) and `integral` everywhere else. `dark`/`local` are global-peak only: the centroid stage falls back to `integral`, bottom-up raises. `find_global_peaks` raises on unknown names (resolve `auto` first). The in-training eval `FindInstancePeaks` of `TopDownCenteredInstanceLightningModule` also decodes with DARK. `--flip_test` (`centered_instance` only, incl. box-seeded; refused for exported dirs and other model types) runs the mirrored crops through the model and averages via `fuse_flip_confmaps`, which swaps channels with `flip_idx` (from skeleton symmetries over the head's `part_names`; none → warn + plain mirror) and resamples the mirrored map by `(W - 1 - (Wc - 1) * stride) / stride` confmap px (the sleap-nn `i * stride` grid; skipping it biases x by `-(stride - 1) / 2` px). Exported ONNX/TRT graphs do grid peaks only: no refinement, no flip-test. See `docs/guides/inference-guide.md#sub-pixel-refinement-and-flip-test`.
- Centroid focal loss: opt-in CenterNet/CornerNet-style penalty-reduced pixelwise focal loss for the centroid confmap head, as an alternative to plain MSE — targets confmap-collapse/duplicate-detection in dense-instance scenes. Config lives on `model_config.head_configs.centroid.confmaps` (`use_sigmoid_activation` + `focal_loss_alpha`/`_beta`/`_pos_threshold`), all defaulting off (byte-identical when disabled). Val/eval loss always stays plain MSE regardless of `alpha` so checkpoints stay comparable. Centroid-only for now (not yet implemented for `single_instance`/`centered_instance`/`bottomup` — tracked in [#736](https://github.com/talmolab/sleap-nn/issues/736)); dataset-dependent results, not a universal win. See `docs/guides/centroid-focal-loss.md`.
- Per-node loss masking (partially labeled / union skeletons) on sleap-io 0.10 (SLP format 3.0; pinned to sleap-io's `release/0.10` git branch via `[tool.uv.sources]` until 0.10.0 is on PyPI): `data/node_weights.py`. Points carry independent `labeled` / `visible` flags; a node's weight is `labeled | visible` (0 only for unlabeled points, e.g. COCO `v=0`; hidden-without-coordinates stays 1 = trained as absent, which is how every pre-3.0 file reads) times the per-file stopgap `provenance["labeled_nodes"]`. Single-instance, centered-instance and bottom-up confmap datasets emit `node_weights` `(1, n_nodes)` ONLY when weights can differ from 1 (`node_weights_active` -> `has_partial_labeling_info` scans for a zero-weight point or `labeled_nodes`; or `data_config.unlabeled_points: ignore`, which zeroes points that are NaN/out of the input after aug), so old projects train byte-identically. Frame-level datasets (single-instance, bottom-up) reduce per-instance weights with a max (`frame_node_weights`, from `process_lf(..., return_instances=True)`); bottom-up also emits `edge_weights` `(1, n_edges)` = endpoint product (`edge_maps.generate_edge_weights`), consumed by the PAF loss via `weights_key="edge_weights"` (repeated over the edge's 2 channels). `data_config.supervise_occluded` (default True): targets come from `providers.instance_points` = `inst.numpy(invisible_as_nan=not supervise_occluded)` (occluded estimates, COCO `v=1`, train as Gaussians; False = weight 0 via `instance_node_weights`); crop sizes, crop boxes (`bboxes.instance_tight_bbox`) and centroids always use `providers.located_points` (labeled with coordinates); instances are skipped only when `is_empty` (no labeled point with coordinates). `data_config.node_loss_mask` (default on) is the master switch. Losses: `training/losses.py::compute_weighted_mse_loss` (Σ s·w·mse / Σ w) and `compute_weighted_ohkm_loss` (per-sample ranking over w > 0), wired via `LightningModel._compute_masked_confmap_loss` / `_compute_ohkm` / `_compute_paf_ohkm`; `trainer_config.online_hard_keypoint_mining.per_sample` (default True; False = legacy `compute_ohkm_loss`). Flip swaps weights with the keypoints; negative frames keep weight 1; `val/loss_unmasked` is logged when weights are active. sleap-io's splits drop `provenance`, so `ModelTrainer._setup_train_val_labels` re-attaches `labeled_nodes` via `carry_labeled_nodes`. Eval scores `evaluation.gt_points` (labeled with coordinates; the COCO evaluator too); centroid-only NaN-padded outputs write non-anchor nodes as unlabeled. Not yet: tiled datasets, multi-class weights. See `docs/guides/partial-labels.md`.
- Top-down (crop-centered) segmentation: model type `centered_instance_segmentation` — a lone `SegmentationHead` on a centroid crop predicting the centered instance's binary mask. `sleap-nn predict` composes a `centroid` dir + the seg dir (or the seg dir alone via a GT-centroid fallback) and emits `sio.PredictedSegmentationMask` on `frame.masks` at full-frame offsets; mask-IoU eval (`--match_method mask`). Training reads per-instance masks from `lf.masks` (linked via `mask.instance`); geometric aug (rotation/scale/translate/flip) co-transforms the GT masks with the image (shared affine matrix, nearest-neighbor; erase/mixup stay image-only), training viz overlays the GT mask, and `trainer_config.eval.enabled` adds instance-level mask-IoU metrics via `SegmentationEvaluationCallback`. Same augmentation/viz/eval parity holds for `bottomup_segmentation`. See `docs/guides/topdown-segmentation.md`.
- Whole-frame semantic segmentation: model type `semantic_segmentation` — a lone `SegmentationHead` on the **whole frame** (no crop, no center/offset, no grouping), the group-free sibling of `bottomup_segmentation` and whole-frame analog of `centered_instance_segmentation`. The head predicts one binary foreground/background map (union of `lf.masks`, `mask.instance` ignored); `sleap-nn predict` auto-detects a lone semantic dir and emits **one instance-less** `sio.PredictedSegmentationMask` (`instance=None`) per frame. Decoding thresholds the foreground at `fg_threshold` → one mask/frame (no `group_instances_from_offsets`). Tiling-compatible (`TiledSemanticSegmentationLayer` stitches a 1-channel fg canvas). **Load-bearing:** the module `forward` returns `{"SegmentationHead": sigmoid(logits)}` (BottomUp-style probabilities, NOT the TopDown template's bare logits) so the whole-frame layer + tiled Gaussian averaging see probabilities; train/val steps use raw logits via `self.model()`. Matching-free eval: `--match_method semantic` (whole-frame fg IoU/clDice/boundary-IoU, no Hungarian) + a `foreground=True` `SegmentationEvaluationCallback` mode. See `docs/guides/semantic-segmentation.md`.
- Bounding-box detection: model types `bbox_centernet` (CenterNet-style: per-category center heatmap + size + sub-cell offset at one stride, penalty-reduced focal + masked L1) and `bbox_ssd` (SSD-style: one `MultiScaleHead` over decoder strides + the bottleneck, anchors auto-sized from the training boxes and written into the saved config, hard-negative-mined softmax CE + smooth L1). One shared stack: GT boxes from `lf.bboxes` or derived in memory from poses/masks via `data_config.bbox_source` (`auto|bboxes|instances|masks`) + `bbox_padding` (`data/bboxes.py::add_bboxes_to_labels`, applied by the trainer before the split); boxes ride the augmentation chain as 4-corner pseudo-instances (`BBoxDataset`, re-boxed + clipped after aug; rotation inflates boxes, so prefer none); per-style target encoders (`CenterNetTargetEncoder` / `SSDTargetEncoder`) and the inverse `BBoxDecoder` (`inference/bbox.py`) used by BOTH val-time eval and `BBoxLayer`, so train metrics and predictions share code. Output: `sio.PredictedBoundingBox` on `lf.bboxes` (`--peak_threshold` = score threshold, `--max_instances` = per-frame cap, `--bbox_nms_iou`). Eval: COCO-style `match_method="bbox"` (mAP@[.5:.95], AP50/75, AR, best-F1 operating point at IoU 0.5) for `sleap-nn eval`, post-training split eval and `BBoxEvaluationCallback` (`eval/val/bbox_*`, broadcast from rank 0 and ALWAYS present in `callback_metrics` on scored epochs, worst value on a failed eval, because the checkpointer may monitor it). Checkpoints/early stopping select on `eval/val/bbox_mAP` when `trainer_config.eval.enabled` (`eval.select_metric` picks `bbox_AP50|AP75|AR|f1` or `val_loss`; `ModelTrainer._bbox_select_metric`), else `val/loss`. ONNX/TensorRT export (`sleap-nn export`) exports the NETWORK only (decoder-ready head outputs, `export/wrappers/bbox.py`); `ExportedBBoxLayer` (a `BBoxLayer` subclass in `inference/layers/bbox.py`) runs the checkpoint path's own preprocessing on the host (size matcher, `input_scale`, stride pad) and decodes with the same `BBoxDecoder`, rebuilt from the exported `training_config.yaml`, so exported and native boxes match. Config generator / TUI / `sleap-nn config --pipeline bbox_centernet|bbox_ssd` emit detector configs (scale 0.5, rotation off, eval on); `sleap-nn info` shows box metrics; legacy `track`/`run_inference` refuses detectors. Not yet: tiling, tracking. See `docs/guides/bbox-detection.md`.
- Box-seeded top-down: a `bbox_*` detector can replace the `centroid` model as stage 1 (`sleap-nn predict -m <detector> -m <centered_instance|multi_class_topdown|centered_instance_segmentation>`). `load_model_assets` builds stage 2 as for its GT-centroid fallback and hangs the detector on `LoadedAssets.detector_assets`; `_select_layer` swaps stage 1 for a `BBoxStageLayer` (`inference/layers/bbox.py`, a `BBoxLayer` that reports box centers as `pred_centroids` + the boxes; `use_gt_boxes=True` derives boxes from GT keypoints), so `TopDownLayer` and its subclasses run unchanged; stage-1 detections are kept as `PredictedBoundingBox` linked to their instances (`box.instance`). The centered-instance model's `data_config.preprocessing.crop_mode` (`fixed` default | `bbox`, + `crop_bbox_aspect` `square|letterbox|stretch`, `crop_bbox_padding` (fraction of the longest side), `crop_bbox_min_size`) picks fixed windows at the box center or box-scaled crops (box resized to `crop_size`; `centered_instance` + `multi_class_topdown` only). ONE rule turns a box into a window for training AND inference: `BBoxCropSpec` / `bbox_crop_windows` in `data/instance_cropping.py` (edge-coordinate windows; Skia at train, `crop_windows` = edge-clamped `grid_sample` x frame coverage at inference, within ~2/255; train pre-crops sqrt(2) at the final scale and re-crops on whole pixels so an un-augmented training crop IS the inference crop). Training boxes use the detector's GT rule (`data_config.bbox_source`/`bbox_padding`, `data/bboxes.py::instance_crop_bbox`); `ModelTrainer._setup_bbox_crop` auto-sizes `crop_size` (median padded window, rounded to max_stride) and `crop_bbox_min_size` (median/4) into the config. A box-scaled model alone uses GT boxes (post-train eval); centroid + box-scaled model, two first stages, and combined detector+top-down export are refused; loaders warn on detector/CI `bbox_source`/`bbox_padding` mismatch and on a fixed-crop CI not trained with `centroid_method: bbox_center`. See `docs/guides/bbox-topdown.md`.
- COCO-faithful keypoint eval + box-seeded top-down: `sleap_nn/evaluation_coco.py` is a numpy port of pycocotools `COCOeval(iouType="keypoints")` on `sio.Labels` (per-threshold matching, every prediction scored, crowd / 0-keypoint ignore regions, maxDets 20, per-node sigmas via `resolve_node_sigmas`, GT area from `/human_meta` else 0.53 x box, `EVAL_PROTOCOLS` coco/ochuman/crowdpose); matches pycocotools (optional `coco` extra, `backend="pycocotools"`, in the dev group for tests). Reported as `coco.*` (`sleap-nn eval --coco --oks_sigmas --coco_protocol`, `run_evaluation(coco_metrics=True)`); native `oks_voc.*` is legacy (`--count_unmatched_as_fp` fixes only its FP accounting). `sleap-nn predict --boxes {gt | dets.json | boxes.slp}` replaces a crop model's stage 1 (`Predictor.from_model_paths(boxes="gt"|"given")` -> `_seed_from_boxes` -> `BBoxStageLayer(use_given_boxes=True)`, fed by `Batch.frame_boxes` from `LabelsProvider.frame_box_fn`); JSON boxes attach by image id (`attach_coco_detections`), `.slp` boxes by video/frame (`transfer_predicted_boxes`). mmpose post-processing lives on `FilterConfig`: `rescore_keypoint_threshold` (score = stage-1 score x mean kpt score > 0.2; default on with `--boxes`) and `oks_nms_threshold`/`oks_sigmas` (`--oks_nms 0.9`; sigmas resolved from the skeleton by `Predictor`). `trainer_config.eval.coco_metrics` adds `coco.*` post-training and predicts top-down splits at `peak_threshold` 0 with rescoring. See `docs/guides/coco-evaluation.md`.
- Tiling (high-res / small-object frames): sliding-window tiling for 4K++ frames where objects are small — cut each frame into overlapping square tiles, run per-tile at native resolution, stitch. **Explicit opt-in** via `data_config.preprocessing.tiling` (`TilingConfig`); everything is inert/byte-identical when off. Geometry (`tile_size`/`overlap`) is auto-sized from labels at train setup, **written into the model config, and parity-checked at inference** (scale parity is a precondition — you cannot tile an existing whole-frame-trained model). Guards (`check_tiling`): pretrained-encoder backbones and `ClassVectorsHead`/`multi_class_topdown` are unsupported; only implemented model types are allowed (else a clear error — no silent no-op). Training uses foreground-aware tile sampling + a frame-grouped block sampler + per-worker frame LRU; inference (`TiledLayer`) stitches per-tile confmaps into one Gaussian-weighted ACC/CNT canvas then decodes once. **Status: Phase A (`single_instance`) is complete** end-to-end (local branch stack `tiling/01-foundations`..`tiling/04-viz-docs`, ~180 tests). `bottomup_segmentation` tiling is Phase C (in progress on `tiling/05-bottomup-seg`). See `docs/guides/tiling.md`, the design/decisions in `scratch/2026-07-03-tiling-highres-smallobjects/` (`03-design`, `04-decisions`, `05-phase0-A-spec`), and the deferred-corners list in `06-phase-c-bottomup-seg.md`.
- Re-ID identity/embedding persistence: predicted animal identity and appearance embeddings persist into the `.slp` via the **simplified** sleap-io `Identity`/`Embedding` data model (sleap-io #535/#536, released in `sleap-io>=0.9.2`, which `pyproject.toml` pins from PyPI). Each detection modality carries a single `identity_embedding: sio.Embedding | None` slot (bare value object wrapping just a `vector` — no space-name/normalized/source metadata) plus `identity`/`identity_score`. (1) **Embeddings:** `sleap-nn predict` on an `embedding` model takes `--save_embeddings {none,slp}` (default `none`); `slp` sets `det.identity_embedding = sio.Embedding(vector)` on EVERY source detection, tracked or not (object-exact via `EmbeddingDataset.mask_idx_list[item_id]["mask_obj"]`; vectors already on the input are cleared first so a file never mixes two models' vectors) and writes the `.slp` **with `save_embedding_vectors=True`** (the #536 default flipped to `False`, so every persist call passes the flag explicitly; identity/Track links persist regardless). The shared embed kernel is `inference/embedding.py::embed_labels`; `predict_embeddings_to_slp` wraps it. Both pose `Instance` and mask `SegmentationMask` embeddings persist (mask-modality `owner_type=3`). The embedding pathway stores **vectors only** — it does NOT fabricate `sio.Identity` from track/class names (existing identities pass through). (2) **Identity:** a multi_class model's class output is interpreted per its head config `class_output` ∈ `{"track"` (default), `"identity"}` (validated at config load). `"track"` (default) emits only the per-video `sio.Track`. `"identity"` ADDITIVELY assigns a canonical global `sio.Identity(name=<class name>)` + `identity_score` (the class probability) alongside the Track — for classes that enumerate **unique individuals**. The simplified `Identity` matches by **name** (#535 dropped `uuid`), so the class NAME is the canonical cross-file/cross-retrain key: no per-class uuid is minted or carried anywhere (the old train-time freeze and the `class_uuids` config field are both deleted; `_multiclass_identities` builds `sio.Identity(name=...)`, dedup by name). Any other `class_output` raises `NotImplementedError` — sleap-io does export `sio.Category`, but mapping classes onto it is not implemented. `Identity` (global) + `identity_score` mirror `Track`/`tracking_score`; GT-vs-predicted is the host class (`PredictedInstance`) + `identity_score is not None`.
- Embedding (appearance / re-ID) tracking: the core `Tracker` gains a `features="embeddings"` mode — an alternative to pose→`oks`, it reads each detection's appearance vector from the single `identity_embedding` slot (`get_embedding` → `inst.identity_embedding.vector`, works on pose `PredictedInstance` *and* mask `PredictedSegmentationMask`) and scores candidates by `cosine_sim` (hardened: `None`/zero-norm/shape-mismatch → `NaN` → no match). Registered in `Tracker._feature_methods`; `apply_tracking` (`inference/tracking.py`) auto-pairs `embeddings`→`cosine_sim` (scored by the vectorized `_appearance_scores` matmul, not a per-pair loop), defaults the candidate maker to `local_queues` when `--candidates_method` is unset (post-occlusion re-ID), skips the single-node/mask auto-resolution that would clobber it, routes to the carrier holding MORE vectors (`embedding_carriers(labels).dominant` — the count-based `count_carriers`/`CarrierCounts` resolver, reusable for other "which carrier?" questions), and rejects motion models (`--use_flow`/`--use_kalman`) + (mask-carrier) pose cull/clean/connect. The same resolver guards `--appearance_weight`: the blend reads the TRACKED carrier's own vectors, so vectors only on the other carrier raise (on a pose+mask file the embedder puts them on the carrier the model was TRAINED on — `head_configs.embedding.embedding.detection_mode`, recorded at training; a pre-field config counts as mask-trained under `burn_in`, else count-based with ties→mask — so a mask-trained model's vectors sit on the masks: blend there with `--features masks`, which tracks the mask carrier); a ≥10% vector-less tracked carrier warns. `cosine_sim` is rejected as the geometric side of a blend. The embedding routes apply these carrier rules (`inference/tracking.py::check_tracking_plan`, shared with `apply_tracking`) BEFORE their inference, not after: WF2 from the input labels + the carrier the model will embed (`inference/embedding.py::embedded_carrier`), the fused WF3 route before its detection stack from the stack's model types (`cli._detection_stack_output`: a segmentation stack, e.g. `centroid` + `centered_instance_segmentation`, emits masks ONLY, so a pose `--features` is refused up front). **`apply_tracking` works IN PLACE** (documented contract, not a copy): it writes tracks onto the input's detections, replaces only each frame's tracked carrier, reorders frames to `(video, frame_idx)`, rebuilds `labels.tracks`, and returns the input — so masks/ROIs/centroids/suggestions/sessions/provenance pass through (callers wanting the input intact pass `labels.copy()`). One fresh `Tracker` per video (track names continue across videos via `Tracker.track_name_offset`; post-cleanup is per video too). In mask-carrier mode each pose linked to exactly one tracked mask (`mask.instance`) inherits its track. Three CLI workflows: **(WF1)** retrack a saved-embeddings `.slp` — `sleap-nn predict -i embedded.slp -t --features embeddings` (track-only path: no model load and no GPU needed, but NOT torch-free -- `import sleap_nn` imports torch via `sleap_nn/__init__` -> `evaluation.py`). **(WF2)** embed + track from a detections `.slp` — `sleap-nn predict -m <embedding_model> -i detections.slp -t`: `predict_embeddings_to_slp(tracker_config=…)` embeds EVERY detection except empty masks (`EmbeddingDataset(include_untracked=True)` enumerates untracked + predicted pose/mask, `group_id=0` placeholder), attaches vectors, runs `apply_tracking`, writes a tracked `.slp`; `--save_embeddings {none,slp}` controls whether vectors persist in it (`none`=tracks only, stripped via `_strip_embeddings` + `save_embedding_vectors=False`). **(WF3)** fused detect+embed+track from a video — `sleap-nn predict -m <centroid> [-m <centered_instance>] -m <embedding> -i video.mp4 -t`: `cli._run_embeddings` splits detection vs embedding dirs (`_is_embedding_model`), runs the detection stack and hands the `sio.Labels` it returns to WF2 in memory (`predict_embeddings_to_slp(labels=...)`, no temp `.slp`). Emits `sio.Track` only (no global `Identity`). Guide: `docs/guides/embedding-tracking.md`.
- Modern MOT trackers (`--tracker sort|deepsort|strongsort|bytetrack|botsort|ocsort|deepocsort`, `sleap_nn/tracking/mot/`): `classic` stays the default and unchanged. The two families' options are mutually exclusive and are checked by `validate_mot_config`, plus `cli._check_tracker_flags` and `_validate_tracker_config_early` at every `predict` route. Classic-only flags with a MOT tracker, MOT-only flags (`--track_buffer`, `--min_hits`, `--track_{high,low}_threshold`, `--new_track_threshold`, `--min_match_similarity`, `--appearance_threshold`, `--mot_param`) with `classic` (except `--mot_param time_base=/body_size=` together with `--link_tracklets`, read by classic's identity linking), and `--tracker` without `-t` are all UsageErrors; `--link_tracklets` is shared. Unset MOT options take the preset (`resolve_mot_params`). For a MOT tracker `max_tracks` means the known animal count, enforced by closed-set linking, and is never derived from `--max_instances`. MOT trackers NEVER drop detections: unconfirmed ones keep `track=None`, tentative frames are retro-labeled on confirmation, and `tracking_score` is the geometric similarity. The appearance trackers (`APPEARANCE_TRACKERS`) need vectors: a video route without an embedding model is refused up front, and deepsort/strongsort refuse vectors on the other carrier. **Gotcha:** `TrackerConfig(scoring_method="oks")` equals the default, so for a MOT tracker it is NOT explicit and stays `auto`; use `mot_params={"similarity": "oks"}`. Per-video resolved params / calibration / linking land in `labels.provenance["tracking"]`, and the provenance builders keep them via `provenance.carry_tracking_record`. Guide: `docs/guides/tracking.md#modern-mot-trackers`.
- Training recipe (ViTPose-style, all off by default): `trainer_config.optimizer.weight_decay` splits every LR param group into named `<group>/decay` / `<group>/no_decay` halves (`training/optim.py::split_weight_decay`: no decay for 1-D params, biases, norms, pos-embeds, CLS/register/mask tokens, timm `no_weight_decay()`); `warmup_steps` on `cosine_annealing_warmup` / `linear_warmup_linear_decay` switches them to per-step updates and `lr_scheduler.multi_step_lr` is always per step (`LightningModel._optimizer_steps_per_epoch` counts from `num_training_batches`, not `max_epochs`); a fixed-length schedule turns unset `early_stopping.stop_training_on_plateau` (`None`) off and nulls the default plateau (`ModelTrainer._setup_schedule_defaults`); `trainer_config.ema` adds the `WeightEMA` callback (EMA weights drive validation and are the checkpoint `state_dict`; online weights under `ckpt["ema"]`); `backbone_config.pretrained.drop_path_rate` ramps 0→rate (HF DINOv2/DINOv3-ViT's uniform rate is converted). Guide: `docs/configuration/trainer.md#optimization`.
- Weight transfer (`init_from`) and freeze schedule: `model_config.init_from` (`InitFromConfig`) loads what fits from another sleap-nn model via `training/weight_transfer.py` -- same key+shape copied, the head OUTPUT layer's per-node channels copied by node NAME (grow/reorder a skeleton; `node_map` seeds new nodes), learned pos-embeds bicubic-resized, everything else skipped and listed in a logged `TransferReport` (`model.transfer_reports`). Source node names come from `checkpoint["sleap_nn_heads"]` (written by `LightningModel.on_save_checkpoint`), else the sibling `training_config.yaml`, else `source_part_names`; with none, channels are copied by position and the report WARNS. `reinit` re-initializes selectors after loading (`blocks[a:b]` use ViT init + `reinit_layer_scale`). One selector vocabulary (`all|backbone|encoder|decoder|neck|head|embeddings|blocks[a:b]|globs`) for include/exclude/reinit/freeze. The `.ckpt` forms of `pretrained_backbone_weights`/`pretrained_head_weights` route through the same loader: **behaviour change** -- a shape mismatch now warns and skips (`init_from.strict: true` raises). `init_from` is skipped when `resume_ckpt_path` is set; inference never passes it. `trainer_config.freeze_schedule` (`EncoderFreezeSchedule` callback) freezes in `on_fit_start`, AFTER `configure_optimizers`, so frozen params keep their layer-decay groups and train once unfrozen; its `setup` hook turns on DDP `find_unused_parameters` (refuses explicit `False`/`static_graph`/non-DDP parallel strategies) because the freeze happens after DDP wrapped the model; refuses `unfreeze_at_step` with the backbone's `freeze: true`. Guide: `docs/guides/init-from.md`.
- HuggingFace foundation-model / ViT backbones: `backbone_config.pretrained` (`architectures/pretrained.py`) wraps any HF vision model as a sleap-nn backbone in three cases: **A** hierarchical encoder (ConvNeXtV2/ResNet/Swinv2/DINOv3-ConvNeXt) → stage pyramid → sleap `Decoder`; **B** encoder-only pooled bottleneck (embedding / re-ID heads); **C** plain ViT (DINOv2/v3, CLIP, SigLIP/SigLIP2, ViT-in21k, MAE, EVA02, PE-Spatial, ...) → `output_hidden_states` taps (default 4 evenly spaced, prefix tokens stripped by count, per-tap fresh LayerNorm) → `vit_neck.py::ViTPyramidNeck` (`dpt` one tap per level / `sfp` ViTDet) at strides `token_stride/4..2*token_stride` → the same `Decoder`; `vit_decoder: classic|simple` (default `unet` = that path) instead runs a ViTPose head on the last tap only (`vit_neck.py::ViTPoseDecoder`: `classic` = deconv 4×4/s2+BN+ReLU blocks then the usual 1×1 head conv, `simple` = ReLU + bilinear then a 3×3 head conv via the backbone's `head_kernel_size` → `Head.make_head(kernel_size=)`), and `vit_final_norm` (default on for those two) normalizes that tap with the encoder's own pretrained final norm instead of a fresh LayerNorm. The input is bilinearly resampled so the token grid lands on a power-of-two `token_stride` (patch-14 DINOv2 → effective 16), so `max_stride` stays 32 (must be a multiple of `2*token_stride`). `mode: auto` resolves from the model's heads (`Model` passes `spatial_heads`): any spatial head → decoder (Case C for a ViT), pooled-only → encoder. Two-tower checkpoints build the vision tower only (`vision_config` via `MODEL_MAPPING`); `timm/...` Hub ids load through transformers' `TimmWrapperModel` + `forward_intermediates` (`timm` is in the `backbones` extra) — the route to **ungated DINOv3** (`facebook/dinov3-*` is gated). MAE gets `mask_ratio=0` + monotone `noise` (it shuffles tokens otherwise). Encoder params that never feed the tapped layers (post-norms, pooling heads, blocks after the last tap) are found by a construction-time probe backward and set `requires_grad=False` (DDP-safe; still in the state dict); blocks after the deepest tap are also skipped at run time (timm `stop_early`, HF `_LeadingBlocks`). Optimizer knobs `trainer_config.optimizer.encoder_lr_scale` / `layer_decay` (the `backbone_config.pretrained` keys are deprecated aliases, moved by `training/optim.py::migrate_encoder_lr_options`) become param groups (`PretrainedBackbone.encoder_param_groups` → `LightningModel._trainable_param_groups`), and scheduler floors/starts scale per group; byte-identical single group when unset. Training setup records `mode: auto` → `decoder` for spatial-head models (`check_output_strides`). RoPE backbones export ONNX with static H/W (`has_rope`; top-down decides from the centroid model, crop models trace at crop size) and TensorRT profiles clamp to static dims. Benchmark + protocol: `scratch/2026-10-20-hf-foundation-backbones/`. Guide: `docs/guides/pretrained-backbones.md`.
